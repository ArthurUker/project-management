## 按主题核对

### 账号等级、密码重置与停用

M-1 明确默认 ADMIN 拥有 `users.reset_password`，并冻结角色权限集合，但没有规定可操作的目标账号等级。R01/B01 证明目标查询没有 `systemRole` 限制；历史真实 JWT 路径证明默认 ADMIN 可重置 SUPER_ADMIN 密码并获得其身份。R01 还观察到 enable/disable 只做权限判断和自我停用限制，未检查目标等级；对更高等级账号停用是否允许仍需治理规则。B01 作为已证明的权限风险保持 `SUPPORTED/P1`，待决策不能反向消解现有可利用证据。

### 自定义角色与强制改密

R01 记录角色创建支持自定义 role code，但用户角色绑定 DTO 仅接受六个系统角色。没有发现签署材料说明自定义角色能否绑定用户、是否仅供模板/未来功能使用。强制改密由 `/auth/password/force` 路由检查，但通用认证中间件不限制该状态调用其他业务 API；M-1 未定义首登强制改密会话的服务端权限边界。现状可确认，期望规则待安全与产品共同裁定。

### 改密后的 access token

R02/N-R02-02 的行为证据来自当前源码：改密/管理员重置后撤销 refresh token 并更新 `passwordChangedAt`，但 access JWT 验证未比较签发时间或会话版本，未查 access 黑名单，因此旧 access token 可在剩余 TTL 内继续请求。R02 报告给出的默认 access TTL 为 900 秒，可配置；现无签署政策定义即时失效还是允许有限宽限期。故保留源码缺口事实，不将政策违规程度或目标 TTL 写成已批准要求。角色变更和账号停用还需确定与改密是否采用相同撤销合同；当前每个请求重新加载用户/权限，停用状态会被拒绝，角色变更的后端权限会按新值装载。

### 注册项目可见和写入范围

M-1 §8.3 明确通用项目规则：最终权限为系统权限与项目成员能力交集，非成员 404，SUPER_ADMIN 是例外；没有注册项目全局可见例外。R04/B21 当前源码及历史隔离证据支持：具 `registrations.view` 的非成员可经注册路由查看，具 `registrations.update` 的非成员可修改项目。若产品希望注册项目打破通用项目范围，需要正式界定全局可见字段、列表和统计、详情关联字段、写操作范围、角色条件、SUPER_ADMIN 审计及导出范围，并按 M-1 变更纪律处理；在批准前沿用一般成员边界，B21 维持 `SUPPORTED/P1`。

### managerId 与 ProjectMember 角色

M-1 定义 OWNER/MANAGER/MEMBER/VIEWER 能力以及 `leftAt IS NULL` 的有效成员规则；没有明确规定 `Project.managerId` 必须对应某一 ProjectMember 行/角色。W10 字段映射说明创建负责人为 MANAGER 成员，R06-N01 则确认 HTTP 负责人变更会同步成员关系而 sync 的通用 managerId 更新不复用该逻辑；R04 也指出 registration PUT 可改 managerId、成员同步差异尚未证明具体身份后果。应由项目治理决定负责人是否必须为有效 MANAGER 成员、是否允许非成员负责人、换任时旧负责人降级/退出/保留何种角色以及并发转交语义。R06-N01 继续作为源码差异发现；业务裁定用于定义修复目标，不否认已观察差异。

### 汇报复提来源状态

W10 枚举列出 `DRAFT/SUBMITTED/REVIEWING/NEEDS_REVISION/REVIEWED`；没有签署状态迁移表说明允许哪些来源状态提交。R09/B10 发现提交入口仅拒绝 REVIEWED，因而可从 SUBMITTED 或 NEEDS_REVISION 再次提交；历史交错还证明版本快照可能落后于正文。需业务确定首次提交、退回修改后复提、重复提交及已提交后换新幂等键重提各自的合法来源状态。任何决定都不能消除 B10 的并发快照证据。

### 父任务、phase、软删与依赖 DAG

W10 表格将 TaskDependency 同项目校验列为目标，并将任务前置跨项目关联标为拒绝；R11/B19 历史探针确认 sync 可建立跨项目 parentId 关系。M-1 未规定任务树是否必须同项目/无环，也未覆盖任意深度依赖 DAG。旧 `docs/pm-audit/06-dev-status-and-plan.md` 曾提出“升级为 DAG 检测”，但这是审阅建议，不是批准的业务不变量。R11 还发现 phase/project/task 软删及物理外键级联语义不同；需明确软删 phase 能否继续被任务引用、父项删除对子项和依赖的处理、恢复时关系是否恢复、删除和同步墓碑如何传播。B19 限定为跨项目边可建立，不声称越权删除他人任务。
