# A/B/C 项目定级政策（P1-e，2026-10-14 用户确认落地）

**方案**：用途定级（方案三）+ 证据深度（方案二）组合。用途决定"按哪套规矩办"，深度决定"要多少证据"。

## 1. 定级定义

| 定级 | 用途定位 | 证据深度要求 | 典型场景 |
|---|---|---|---|
| **A** | 科研 / 教育 | 记录完整即可；验证类可简化，但须记录简化理由 | 方法学习、内部研究、教学演示 |
| **B** | 食品安全 / 动物水产检测 | **预定义接受标准 + 重复性证据**；放行标准必须预先定义 | 按标准方法或客户要求执行的检测项目 |
| **C** | 对外交付 / 产品化 | **完整 V&V + 风险闭环 + 版本冻结**；交付包必须完整 | 客户正式使用、对外发布 |

## 2. 定级时机与记录

- **p1「项目价值与 Go/No-Go 判断」**：立项时确定定级与理由，记入**项目一页卡**（五类资料之一）。
- 定级是**项目级属性**，不随单个任务改变；确需变更时按 p2 问题/风险/变更台账记录并评估对已有结论的影响。

## 3. 定级 → 验证等级的映射（p8 分析性能验证）

母版 p8 原已内置「按等级 / A 类最低验证执行 / C 类增强验证」结构，映射关系：

| 定级 | 执行哪组验证 | 说明 |
|---|---|---|
| A | A 类最低验证执行 | B/C 定级**不得**以 A 类替代 |
| B | 完整验证（灵敏度/LoD、特异性、重复性批间、抗干扰） | 全部执行，接受标准须预先定义 |
| C | C 类增强验证 + 风险闭环 + 版本冻结 | 在 B 的基础上增加增强项 |

## 4. 可按级裁剪的任务（已写入母版 `regulatory_notes` 的 `[分级要求]`）

| 任务 | A | B | C |
|---|---|---|---|
| p8 性能验证方案设计（按等级） | A 类最低 | 完整验证 | C 类增强 + 风险闭环 |
| p8 A 类最低验证执行 / C 类增强验证 | A 执行 / — | — / — | — / C 执行 |
| p10 放行标准与批检 | 可简化（记理由） | **必须预定义** | **必须预定义** |
| p9 有效期与储运条件确定 | 可简化（记理由） | 按用途 | **必须完整** |
| p12 产品发布评审 | 可按需 | 可按需 | **必须完整** |
| p13 客户交付文件 | 可按需 | 可按需 | **必须完整** |

**裁剪规则**：① 不得"静默裁剪"——任何按级简化都必须在任务记录中写明理由；② 无效/失败记录不得丢弃，也不得当作阴性结论；③ 对外声称范围不得超过定级对应的证据范围。

## 5. 边界（不伪称生效）

- 本政策是**内容约定**，系统当前**不自动裁剪**任务清单；裁剪预览与理由是 P2 的能力范围。
- A/B/C 定级**不得**用于把 CONDITIONAL 任务改写为 REQUIRED 或反之（适用性语义独立于定级）。
- 若将来涉及人用医疗注册用途，需另设分支模板并重新评估定级定义（本轮母版不含注册路径）。

## 6. 共同底线（无论哪级都适用）

1. 样本/靶标/用途和不允许解释明确；2. 成果状态、系统版本、试验样本和关键数据可追溯；
3. 每次试验的必要阴阳性及过程控制策略有依据，无效不作阴性；4. 关键结论有预定判断、原始证据与异常说明；
5. 对外声称/试用/发布范围不超过证据和适用规则允许范围；6. 关键变更能识别已受影响的结论。
