# 水产病原数字微流控芯片：母版情景走读

日期：2026-10-13。性质：假设案例的桌面走读；无实际实验、性能验收或运行测试，不是已批准产品规格。

## 1. 案例边界

假设：已有一套可引用版本的数字微流控扩增平台，拟开发某水产病原核酸检测产品，候选用途包括养殖研究/监测，候选样本包括动物组织或养殖水。尚未指定病原、样本采集方法、用户、检测原理及现有平台证据；不能据此判定监管路线、性能合格、所需样本量、周期或所需人员。

首个动作应当是选定一个用途和样本组合。不能把“组织＋水样＋所有病原＋各种仪器＋现场条件”作为一个没有边界的首期目标。

## 2. 逐阶段走读

| 原阶段 | 需要在此回答的问题 | 本案例适配及最小证据 | 可并行/复用及停止边界 |
|---|---|---|---|
| p1 需求与立项 | 研究、动物疫病诊断、监测还是其他用途？组织还是水样？结果能作何解释？ | 一页卡写明对象、样本、用户、地点、允许/不允许用途及成果状态 | 用途未知可以做限定研究；不能据此批准外部诊断用途 |
| p2 管理机制 | 谁负责分子/前处理/芯片/应用，哪些资源与资料缺失？ | 责任与资源栏、关键风险、变更记录；先判定 A/B/C | 同一人兼任可登记，关键外部使用结论需明确授权和适用复核 |
| p3 技术设计 | 哪些靶标/变体和近缘对象？提取与平台接口是什么？ | 靶标范围、体系/内控/对照与接口、已有平台基线索引 | 序列设计可与样本采购并行；检测方法未定时不能通用套 Ct 阈值 |
| p4 样本 | 实际样本谱、来源状态、保存和目标真值如何确定？ | 组织和水样分别建方案；开发材料与独立确认材料用途区分 | 分批到位；无真值材料可做操作研究，但不能据此证明真实样本准确性 |
| p5 前处理 | 组织处理与水样采集/富集是否为不同流程？ | 对具体流程的回收/抑制/携带及上样规格评估 | 可复用相同基质的受控方案；新基质不能仅复用旧 Ct 结论 |
| p6 片外扩增 | 体系是否能在相应提取背景中工作？控制能否解释失败？ | 探索计划及数据、阴阳/适用过程控制、判读初版 | 用开发材料先筛选，与前处理迭代；不得将反复调优材料直接充当独立确认集合 |
| p7 芯片集成 | 含盐/蛋白/黏度或杂质变化会怎样影响液滴、表面及扩增？ | 完整流程轨迹、适用的桥接、异常归因、系统配置单 | 仅对新差异做重点验证；电极/介电层项目按实际驱动架构判定 |
| p8 性能 | 需要证明哪个样本、流程和版本的检测范围？ | 预先方案、低水平/特异/重复/干扰及无效处理，证据对应声称 | 探索先行；正式结论前确认批次代表性。组织检出限不直接等同水样每体积检出限 |
| p9 稳定性 | 产品怎样储运，试用多久，已有数据能支持什么？ | 当前配置/包装、观察点与数据切点、可支持期限 | 长期支线与其他工作并行；未有依据的保存期限不能先写成批准标签 |
| p10 小试/QC | 验证/试用批是否对应最终工艺和关键物料？ | 代表性及批次用途判断、批记录、适用检验与批准 | 不强行移动整个阶段；把确认批就绪列为正式验证输入 |
| p11 应用 | 目标操作者在真实条件能否按说明得到可解释结果？ | 受控说明、使用环境及操作记录、失败/复测、比较方法及不一致处理 | 先限定场景试用；不能由纯化核酸实验推断样本到结果、现场及诊断用途全部成立 |
| p12 发布 | 哪些范围被数据和适用要求支持？ | 发布/受限试用决定及版本、风险、说明与支持准备 | 条件不具备则收缩声称或继续研究；不按进度条自动发布 |
| p13 归档/移交 | 原始证据、缺口及长期观察交给谁？ | 索引、受控文件、接收人、未决行动与跟踪责任 | 归档已有证据，不补造先前应批准的记录 |

## 3. 五个必须覆盖的反例

以下是未来计划中的检查问题，没有在本轮执行：

1. 反应阳性对照正常，但真实样本过程控制异常：能否输出无效并定位范围，而非自动输出阴性？
2. 管式扩增正常，芯片完整流程失败：能否区分液体操作、提取、抑制、温控、光学或算法问题，而非一律调整配方？
3. 组织样本已有证据，新增养殖水：是否触发采集/富集/单位/抑制和应用验证，而不是仅改样本名称？
4. 相邻高低水平或空白出现非预期信号：是否保留全部失败、关联样本/批次/路径并处置污染，而非删除失败运行？
5. 冻结后换油相/表面/供应商或算法：是否识别受影响的操作、保存、判读和低水平结论，决定桥接或补验？

## 4. 排期走读

可讨论的关系：

```text
用途和样本范围确认
    ├─ 样本/参考材料分批就绪
    ├─ 靶标与引物/体系开发
    └─ 既有平台基线及差异评估
               ↓
前处理与扩增有条件并行 → 联合兼容/芯片桥接 → 系统配置确认
               ↓
代表性验证/试用产品就绪
    ├─ 正式性能证据
    ├─ 稳定性观察（按已有数据支持范围评审）
    └─ 应用/操作者验证（满足相应启动条件）
               ↓
受控说明及证据决定 → 限定试用/发布 → 移交和持续跟踪
```

这些支线仍可能争用同一人、设备或样本，画成并行不等于实际能并行。本案例没有填入几周、几人、样本数或接受阈值，因为缺乏真实输入。所需的最小排期资料是：关键任务实际人时、外部等待、共享资源、已有证据复用范围、长周期观察和返工记录。

## 5. 走读结论

13 阶段可以容纳这个案例，不需要先增加阶段。优先完善用途/基质选择、过程控制、芯片差异、批次代表性、完整失败统计以及对外使用决定。该结论是母版可讨论的适配方向，不是案例已经验证可用。
