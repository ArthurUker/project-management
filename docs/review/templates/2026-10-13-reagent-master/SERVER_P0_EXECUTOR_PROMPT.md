五、固定技术方案，不自行扩大设计

2. 有效 config 决定其已表达的阶段/任务顺序、启用状态、连线、节点信息和编辑值。
3. config 未携带的领域字段，按相同任务 ID 从结构化行补全：description、taskType、applicability、regulatoryPriority、expectedDeliverable、regulatoryNotes、estimatedHours、assigneeRoleCode 等。
4. 明确提供的 false/0/空值不得因为真假值判断被旧行覆盖；每字段允许清空与合法值按现有合同验证。不把 null 无条件当缺失。
5. config 中新建且没有结构化行的节点可以存在；字段使用明确兼容默认值，不能伪造交付物或角色。
6. 保留 type、phaseInfo、completionTip、allowSkip、events、eventTemplates、milestones、布局和子阶段数据的往返表达。结构化 isMilestone/工时等不得在无意义转换中静默丢失。
7. 编辑保存时写完整、可版本识别的规范 JSON 对象；这是接口/配置格式版本，不是新增产品发布政策。读取仍兼容旧字符串。
8. 已存在但损坏、重复 ID 或引用不合法的配置，不得静默退回旧表并显示成功；返回明确错误，保留原数据，不自动修复生产记录。
9. 保护未被本轮编辑器支持的合法字段，避免窄 DTO 重写时丢弃；未知危险或不合法输入按受控解析拒绝，禁止直接展开请求到 ORM。
